# Our Hawaii Honeymoon

2026년 12월 12일~26일, 두 사람의 하와이 신혼여행 일정표입니다. 제공받은 실제 계획과 예약 정보를 사용하며, 예약 여부가 불명확한 항목은 확정으로 표시하지 않습니다.

React + TypeScript + Vite로 만든 정적 사이트입니다. 백엔드, DB, 로그인, API 키 없이 동작합니다. 날짜별 일정, 숙소·항공·교통, 섬별 전체 보기, 기기 내 준비 체크리스트를 제공합니다.

## 설치와 실행

Node.js **22.12 이상**이 필요합니다. 이 프로젝트 폴더에서 실행합니다.

```sh
npm ci
npm run dev
```

개발 서버 주소는 터미널에 표시됩니다. 기본 주소는 `http://127.0.0.1:5173/`입니다.

현재 Windows 작업 환경에서는 Node.js가 PATH에 없으므로, 기존 작업 폴더의 Node.js를 찾아 실행하는 편의 스크립트도 제공합니다. 상위 `codex` 폴더에서:

```powershell
powershell -ExecutionPolicy Bypass -File .\hawaii-honeymoon\start.ps1
```

이 스크립트는 기존 `ticketlink-analysis-20261005/tools/node-v22.20.0-win-x64`를 대체 실행 경로로 사용합니다. 다른 컴퓨터에서는 Node.js를 설치하고 일반 npm 명령을 사용하면 됩니다. 의존성이 없으면 `npm ci`를 먼저 실행하며, 서버가 실행되면 기본 브라우저를 엽니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다.

```sh
npm test                 # 날짜·항공·숙박·상태·지도·저장 데이터 검증
npm run build           # TypeScript 검사 + dist/ 프로덕션 빌드
npm run preview         # dist/ 로컬 미리보기
npm run test:browser    # 실제 브라우저에서 모바일·PC 기능 검증
```

로컬 브라우저 테스트는 설치된 Google Chrome을 사용합니다. CI에서는 Playwright Chromium을 사용하며, 워크플로에서 자동 설치합니다. 브라우저 테스트를 실행하기 전에 `npm run build`가 필요합니다. `test-results/`에 생성되는 화면 캡처는 Git에서 제외됩니다.

## 일정 수정 위치

**`src/data/trip.ts`**가 일정의 원본입니다.

| 데이터 | 내용 |
| --- | --- |
| `days` | 날짜별 타임라인·방문 순서·출발 숙소·주의 메모 |
| `stays` | 숙소 3곳과 체크인·체크아웃일 |
| `flights` | 항공 5편, UTC 오프셋을 포함한 실제 시각과 IANA 시간대 |
| `places` | 장소명과 Google Maps 검색어. 미확인 장소는 검색어 없이 메모만 기록 |
| `mapLocations` (`src/data/mapLocations.ts`) | 출처를 확인한 지도 대표 좌표와 지점 설명. 미확인 숙소·집합지는 좌표 없음 |
| `transport` | 렌터카·택시·투어 차량 |
| `tasks` | 준비 항목·초기 완료 상태·관련 날짜와 장소 |

UI는 `src/App.tsx`, 스타일은 `src/styles.css`, 날짜·시간대·지도·저장 처리는 `src/lib.ts`에 있습니다.

날짜별 지도는 `src/DayMap.tsx`, 지도 스타일은 `src/map.css`, 목적지 번호와 연결 구간 처리는 `src/mapModel.ts`에 있습니다. Leaflet으로 확대·축소, 목적지 선택, 구간별 보기와 한국 구간 보기를 제공합니다. 선은 방문 순서를 잇는 직선이며 도로·비행 경로 계산이나 소요시간 추정이 아닙니다. 위치가 미확인인 중간 지점은 선을 끊고 임의 좌표를 사용하지 않습니다. 공원·해변·지역의 핀은 대표 위치이며, 실제 입구·주차·집합 장소와 다를 수 있습니다. 출처와 설명은 각 좌표 데이터에 기록합니다.

거리 지도 배경은 [OpenStreetMap](https://www.openstreetmap.org/copyright) 타일을 브라우저에서 불러오며 API 키가 필요하지 않습니다. [타일 이용 정책](https://operations.osmfoundation.org/policies/tiles/)에 따라 출처 표시, 브라우저 캐시와 Referer를 유지하고 타일 일괄 다운로드나 오프라인 프리패치를 하지 않습니다. 위치 검색이나 경로 계산 API는 사용하지 않습니다. 배경을 끄거나 불러오지 못한 경우에도 저장된 목적지·동선과 [Natural Earth](https://www.naturalearthdata.com/) 1:10m 해안선(`src/data/hawaii-land.json`, public domain)이 남습니다. 해안선은 지형 개요용이며 도로 지도가 아닙니다. 한국 구간의 거리 지도 배경은 인터넷 연결이 필요합니다.

- 상태는 `확정`, `계획`, `선택`, `확인 필요`만 사용합니다.
- 날짜 전용 값은 `YYYY-MM-DD`이며 요일은 UTC를 명시해 계산합니다.
- 항공은 `2026-12-12T20:50:00+09:00`처럼 오프셋을 저장하고, `Asia/Seoul` 또는 `Pacific/Honolulu`로 현지시간을 표시합니다.
- 하루 일정은 작성된 이동 순서 그대로 표시합니다. 서로 다른 시간대의 시각 문자열로 정렬하지 않습니다.
- 숙박은 `checkIn <= date < checkOut`으로 판정하므로 체크아웃일 밤을 포함하지 않습니다.
- 12/17·12/21은 출발·도착 숙소, 12/25는 호텔 숙박 없음으로 표시합니다.
- 선택 날짜와 화면은 `#view=daily&date=2026-12-24` 형식으로 URL에 저장합니다. 여행 기간 밖에서는 첫날이 열립니다.
- 방문 순서는 경로 계산 결과가 아닙니다. 검색어가 알려진 연속 장소에만 길찾기를 제공합니다. 미확인 숙소나 정차지를 건너뛰어 잘못된 전체 경로를 만들지 않습니다.
- 가격은 제공받은 과거 예약 확인 금액이며 실시간 가격이 아닙니다.

준비 체크는 ‘체크 내용 저장’ 버튼을 누를 때 `localStorage`의 `hawaii-honeymoon.checklist.v1` 키에 저장됩니다. 체크 직후에는 임시 변경 상태로, 같은 화면 안의 메뉴를 이동해도 유지되지만 저장 전 새로고침하면 마지막 저장 상태로 돌아옵니다. ‘저장 전 변경’ 개수와 저장 성공·실패를 표시하며 ‘변경 취소’로 마지막 저장 상태를 복원할 수 있습니다. 저장 실패 시 임시 변경을 유지해 다시 시도할 수 있습니다. 다른 기기·브라우저와 자동 동기화되지 않으며, 체크해도 `trip.ts`의 예약 상태는 바뀌지 않습니다. 태스크 `id`와 저장 키를 유지하므로 기존 기록은 그대로 불러옵니다. 기본 완료값이 바뀌어도 기존에 저장된 체크 값이 우선하며 강제로 덮어쓰지 않습니다. 새 항목은 초기값으로 추가됩니다. 저장소 차단·손상 시 기본값으로 안전하게 동작합니다.

Google Fonts는 선택적인 글꼴 로딩에만 사용합니다. 로딩되지 않으면 시스템 글꼴로 표시되며 핵심 기능은 유지됩니다. 지도 링크를 열 때는 인터넷 연결이 필요합니다. 사이트 전체의 오프라인 캐시 기능은 이번 범위에 없습니다.

## GitHub Pages 배포

전용 저장소는 `https://github.com/qkqhticyc-lab/hawaii-honeymoon`입니다. 투자 사이트와 저장소·워크플로가 분리되어 있습니다. GitHub Pages 배포가 성공하면 공개 주소는 `https://qkqhticyc-lab.github.io/hawaii-honeymoon/`입니다.

1. 배포를 진행할 때 **이 폴더의 내용**을 GitHub 저장소 루트에 넣습니다. 상위 `codex` 폴더 전체를 올리지 않습니다.
2. GitHub 저장소 `Settings → Pages → Build and deployment → Source`에서 **GitHub Actions**를 선택합니다.
3. `.github/workflows/pages.yml`은 **main 브랜치 push 시 자동 실행**됩니다. 별도 하와이 사이트의 코드만 빌드·배포합니다.
4. 수동 재배포는 GitHub의 `Actions → Publish to GitHub Pages → Run workflow`에서 실행할 수 있습니다.
5. 워크플로는 설치 → 데이터 테스트 → 타입 검사·빌드 → 브라우저 테스트 → Pages 업로드·배포 순서로 실행합니다. 배포 URL은 `github-pages` 환경에 표시됩니다.

Vite의 `base: './'`와 해시 탐색을 사용하므로 `https://사용자.github.io/저장소/` 하위 경로와 사용자 도메인에서 정적 자산을 상대 경로로 불러옵니다. 테스트 서버는 실제 빌드를 `/honeymoon/` 하위에 올려 이 동작을 검증합니다. 경로 라우터를 사용하지 않아 `404.html` 복사나 SPA rewrite 설정이 필요하지 않습니다.

GitHub Pages 설정 참고: [Vite 공식 배포 문서](https://vite.dev/guide/static-deploy.html#github-pages).

## 검증

- 날짜·요일·시간대·항공 순서와 소요시간, 5+4+4박, 예약 상태, 미확인 장소, 저장 데이터 복구 테스트
- Chrome 390×844 / Asia-Seoul, 1440×1000 / Pacific-Honolulu 환경에서 15일 전체와 4개 화면 점검
- 날짜 선택·새로고침·뒤로 가기, 체크 저장·필터, 키보드 포커스·메모 펼치기, 버튼 높이 44px 이상, 지도 링크, 저장소 실패 처리 검증
- 프로덕션 빌드의 저장소 하위 경로 자산 로딩과 개발 서버 HTTP 응답 확인

실제 여행 예약이나 최신 운영 상황을 조회·변경하는 기능은 없습니다. 사용자가 제공한 계획과 예약 화면 기준의 기록입니다.
